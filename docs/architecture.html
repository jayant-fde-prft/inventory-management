System Architecture

Factory Inventory Management System

A two-service demo app: a Vue 3 single-page frontend talking over HTTP to a Python FastAPI backend, which serves data straight out of JSON files held in memory. No database, no auth — built for demoing, not production.

The 30-Second Version

Think of it like a restaurant with an open kitchen. The frontend (Vue) is the dining room — it's what customers see, and it takes their orders (filter selections, page navigation). The backend (FastAPI) is the kitchen — it receives orders over a ticket rail (HTTP requests) and prepares a response. But there's no walk-in freezer here: the "ingredients" are just JSON files read into memory once when the kitchen opens (server start) and re-read fresh every time the server restarts. Nothing is stored back to disk — it's a demo kitchen, not a real supply chain.

Data Flow — Loading the Dashboard

What actually happens when a user opens the app and lands on the Overview tab.

1
Browser requests localhost:3000
Vite serves the compiled Vue app. Vue Router matches / to Dashboard.vue.
2
Dashboard.vue mounts and reads current filters
Filter state (warehouse, category, status, month) lives in the shared useFilters composable — set via the top-of-page FilterBar and read by every view.
3
api.js fires parallel axios calls
e.g. api.getDashboardSummary(filters) — filters are serialized into query params like ?warehouse=all&category=Sensors.
4
FastAPI receives the request on port 8001
CORS middleware allows the cross-origin call from port 3000. The route function runs apply_filters() / filter_by_month() over the in-memory Python lists.
5
Pydantic validates and shapes the response
The filtered result is coerced into the declared response model (e.g. List[InventoryItem]) and serialized to JSON.
6
Vue stores the response in a ref and recomputes
Raw data lands in refs like allOrders; anything derived (totals, chart series) is a computed() that reruns automatically.
7
Template re-renders
Stat cards, tables, and SVG charts update. Changing a filter jumps back to step 2 — no page reload.

Worth Knowing

Everything is in-memory
JSON files load once at server startup (mock_data.py). Any change made through the API only lives until the next restart — fine for a demo, a trap if someone expects persistence.
No auth, wide-open CORS
allow_origins=["*"] and zero authentication. Explicitly called out in the server's own CLAUDE.md as dev-only — would need real auth and origin locking before this goes anywhere near production.
Frontend calls routes the backend doesn't have
api.js defines getTasks, createTask, and createPurchaseOrder hitting /api/tasks and /api/purchase-orders — but main.py never defines those routes. Any component that calls them (e.g. the Tasks modal) will fail against this backend as-is.
Filters are one shared source of truth
The useFilters composable is a module-level singleton (refs declared outside useFilters()), so every component that imports it reads and writes the *same* filter state — that's how the FilterBar updates every page at once.
